# Keep CPE tooling projections at the render boundary

ADR-0006 and ADR-0009 remain the only component-identity model: recipe fragments, vulnerability matching, requirements-matrix evidence, and alignment-profile evaluation represent independently assessable logical component instances. There is no legacy identity switch. The optional `CYCLONEDX_EXPAND_CVE_PRODUCT_ALIASES` and `CYCLONEDX_DEDUPLICATE_CPE_COLLISIONS` flags instead transform the completed ordinary SBOM/VEX view after fragment merging and VEX reference resolution. Expansion precedes deduplication, so secondary aliases from different recipes participate in the same final CPE projection; absorbed instance references, file ownership and VEX targets follow the surviving logical instance. When a merged recipe has a distinct primary correlation CPE, that CPE remains visible as a marked alias row without inheriting files or VEX status.

This view trades truthful per-instance inventory for CPE-keyed tooling correlation. With both flags off, the truthful output is unchanged. Included, imported and embedded graphs are not projected. Neither projection may be selected with an alignment profile: parse-time configuration validation rejects either flag rather than treating projected rows as evidence under a second identity model.
